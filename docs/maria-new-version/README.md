# MARIA — نسخه جدید

این شاخه با نام «نسخ جدید» برای بازسازی مستقل هسته اجرایی MARIA ساخته شده است. نسخه فعلی سیستم دست‌نخورده می‌ماند تا نسخه نصب‌شده و نسخه جدید با یک سناریوی یکسان مقایسه شوند.

## هدف اصلی

MARIA نباید به جمله‌های از پیش تعریف‌شده وابسته باشد. کاربر باید هدفش را با زبان طبیعی، محاوره‌ای، کوتاه، طولانی، دارای غلط املایی یا با هر ترتیب کلمه‌ای بگوید و MARIA:

1. منظور را تشخیص دهد.
2. ابزار درست را خودش پیدا کند.
3. مجوز و ریسک را بررسی کند.
4. کار را اجرا کند.
5. نتیجه واقعی را بررسی کند.
6. فقط در صورت رسیدن به نتیجه نهایی بگوید «انجام شد».
7. در صورت شکست، راه دیگری امتحان کند یا گزارش قابل‌فهم بسازد.

## قرارداد اجرای هدف

هر درخواست اجرایی باید ابتدا به یک برنامه ساختاریافته تبدیل شود:

```json
{
  "goal": "canonical.intent",
  "arguments": {},
  "confidence": 0.0,
  "risk": "low|medium|high|critical",
  "privacy": "local|redacted|online_allowed",
  "candidateTools": [],
  "preconditions": [],
  "postconditions": [],
  "fallbacks": [],
  "requiresConfirmation": false
}
```

مدل فقط پیشنهاددهنده است؛ اجرای واقعی با Tool Registry، PermissionPolicy و Verifier انجام می‌شود.

## خانواده‌های قابلیت

به‌جای نوشتن هزار فرمان جدا، واژگان، غلط‌های رایج، مترادف‌ها، فعل‌ها، هدف‌ها و ترتیب جمله‌ها ترکیب می‌شوند. این روش بدون نگهداری هزار if مستقل، بیش از هزار شکل گفتاری برای هر مجموعه قابلیت را پوشش می‌دهد.

خانواده‌های پایه:

- صدا: زیاد، کم، صفر، قطع، وصل، میوت، درصد مشخص، خروجی صوتی
- نور و نمایشگر: افزایش، کاهش، درصد، خاموشی صفحه، نمایشگر انتخابی
- برق و نشست: قفل، خواب، خروج از حساب، راه‌اندازی مجدد، خاموشی
- برنامه‌ها: باز کردن، بستن، تمرکز، جابه‌جایی، پیدا کردن برنامه نصب‌شده
- مرورگر: Google، URL، جست‌وجوی واقعی، تب، تاریخچه، دانلود، پروفایل
- پروفایل Chrome: نگاشت Amir Mohamed به‌عنوان پیش‌فرض و شرکت برای Rubika/WhatsApp
- فایل: پیدا کردن، باز کردن، بستن، ذخیره، ساخت، تغییرنام، کپی، انتقال، حذف امن
- پوشه و فضای ذخیره‌سازی: فهرست، اندازه، فضای خالی، جست‌وجوی همه درایوها
- فشرده‌سازی: ZIP، استخراج، افزودن و بررسی محتویات
- رسانه: پخش، مکث، توقف، بعدی، قبلی، پیدا کردن آهنگ/فیلم
- دسکتاپ: مرتب‌سازی، گروه‌بندی، انتقال و قرنطینه فایل‌های بی‌استفاده
- سطل زباله: فهرست، بازیابی، خالی‌کردن با تأیید
- نصب و حذف: برنامه، وابستگی، به‌روزرسانی، بررسی نسخه
- Windows: تنظیمات، شبکه، Wi‑Fi، Bluetooth، امنیت، Storage، Update
- تحقیق: جست‌وجوی چندمنبعی، سایت مشخص، استخراج، مقایسه، استناد
- دانش: وب زنده، اسناد محلی، حافظه پروژه، ترجیحات کاربر
- پنجره و رابط: کلیک، تایپ، اسکرول، تغییر اندازه، تمرکز، بستن
- کدنویسی: پیدا کردن فایل، اصلاح، تست، build، بررسی diff و بازگشت
- گزارش و یادگیری: ثبت شکست، پیشنهاد Skill، replay خشک و ارتقای تأییدشده
- کاراکتر: انتخاب، لباس، اکسسوری، حالت چهره، حرکت و پیش‌نمایش Draft

## قواعد مهم

- زبان پیش‌فرض فارسی است؛ انگلیسی فقط وقتی کاربر بخواهد یا برای کد/نام فنی لازم باشد.
- پاسخ انگلیسی یا نامربوط باید توسط ResponseValidator رد و دوباره تولید شود.
- هیچ ابزار موفق اعلام نمی‌شود مگر اینکه postcondition آن تأیید شده باشد.
- حذف دائمی، نصب، ارسال پیام، تغییر تنظیمات حساس و خاموشی سیستم از PermissionPolicy عبور می‌کند.
- فایل‌های نامطمئن ابتدا به قرنطینه یا سطل زباله منتقل می‌شوند.
- کلیدها، توکن‌ها و اطلاعات خصوصی وارد prompt، حافظه یا گزارش عمومی نمی‌شوند.
- خطاها با runId، مرحله، ابزار، علت، تلاش مجدد و پیشنهاد بعدی ذخیره می‌شوند.
- مدل‌ها از طریق Provider Registry قابل‌تعویض هستند؛ نام مدل در منطق اصلی hard-code نمی‌شود.
- سرویس آنلاین رایگان مسیر کمکی است، نه تنها مغز. Ollama/local fallback باید باقی بماند.
- محدودیت مصنوعی تعداد دستور حذف می‌شود؛ محدودیت واقعی مدل، سخت‌افزار و سهمیه سرویس‌ها باید در وضعیت سیستم نمایش داده شود.

## ترتیب پیاده‌سازی

1. Snapshot و مقایسه source فعلی با نسخه نصب‌شده.
2. Universal Intent Engine و قرارداد ActionPlan.
3. Planner، Executor، Verifier و Recovery.
4. صف، streaming، لغو، retry و اجرای پس‌زمینه.
5. پروفایل‌های Chrome و BrowserController قابل‌تأیید.
6. File Intelligence و عملیات امن فایل.
7. Research Runtime و گزارش منابع.
8. Memory/Privacy و Skill Learning تأییدشده.
9. Character Studio و Draft/Apply/Cancel.
10. بسته نصب، آیکون ویندوز، update و rollback.

## معیار پذیرش

نسخه جدید باید این سناریوها را واقعاً اجرا و تأیید کند:

- «صدا رو ببند»، «ساکتش کن»، «ولوم صفر»، «صدا رو تا آخر زیاد کن» و «آروم‌ترش کن».
- «نور رو بیشتر کن»، «روشنایی رو روی ۶۰ درصد بذار» و «صفحه رو تاریک کن».
- «فلان چیز رو سرچ کن» و بازشدن Google با query واقعی در پروفایل Amir Mohamed.
- بازکردن Rubika/WhatsApp در پروفایل شرکت.
- پیدا کردن و بازکردن فایل با نام ناقص یا بدون مسیر.
- ساخت پوشه، کپی، انتقال، تغییرنام، ZIP و استخراج.
- تحقیق در سایت‌های مشخص با گزارش و منبع.
- شکست مدل یا ابزار و ساخت گزارش فارسی قابل‌فهم.
- پاسخ سؤال ساده و تخصصی فارسی بدون پاسخ تصادفی انگلیسی.
- ارسال چند پیام پشت‌سرهم، لغو اجرا و ادامه پاسخ طولانی.
- تغییر کاراکتر در Draft، پیش‌نمایش زنده، Apply، Cancel و Reset.
- مقایسه نتیجه نسخه جدید با نسخه نصب‌شده قبل از هر جایگزینی.

این فایل قرارداد محصول است؛ پیاده‌سازی باید بعد از بررسی فایل‌های واقعی و بدون ادعای موفقیت پیش از تست انجام شود.
