## ۲. مهندسی دقیق صورت از تصویر `1000311032.jpg`

تصویر مرجع از سوپربیضی `n = 2.7` استفاده می‌کند:
```text
|x/rx| ^ 2.7 + |y/ry| ^ 2.7 = 1
x(t) = rx * sign(cos(t)) * |cos(t)| ^ (2/2.7)
y(t) = ry * sign(sin(t)) * |sin(t)| ^ (2/2.7)
```
- نسبت تقریبی عرض به ارتفاع در نقشهٔ مرجع: `2×1.14R / 2×0.88R ≈ 1.295`. پیشنهاد پایه: `210×162` یا نسخهٔ mini متناسب. تنظیم سطوح با گرافیک برداری و نور نرم، نه تصاویر تار.
- دو چشم گرد روی سطح محدب صورت؛ yaw/pitch کنترل‌شده و با محدودیت دامنه. نشان وضعیت روی گوشهٔ بالایی چپ همراه حرکت صورت، نه یک نقطهٔ مستقل رها شده.
- ناحیهٔ specular در بالای راست؛ هاله و blush با opacity محدود. برای خط چشم/پلک و گونه از مقادیر قابل تنظیم استفاده شود.
- دو دستِ کوچک معلق با تأخیر حرکت جزئی و دامنهٔ محدود؛ در حالت mini در صورت کمبود جا می‌توانند پنهان یا نزدیک شوند.
- نسخهٔ اجرایی: مسیر پارامتریک SVG، ۲-۳ gradient سبک، حرکت مشتق‌شده از pointer، حفظ نسبت ابعاد و کاهش جلوه‌ها روی سخت‌افزار ضعیف.

## ۳. طراحی سیستم مشترک (Motion + UX + Meaning)

### State Registry
| وضعیت | چهره و رنگ | گذار و منبع حقیقت |
|---|---|---|
| idle | سفید، چشم باز، هالهٔ خنثی | عدم وجود عملیات |
| greeting | لبخند/پلک/دست | تعامل واقعی موس/کلیک |
| listening | آبی ملایم، هالهٔ کوچک | دریافت میکروفون فعال |
| thinking | بنفش کم‌رنگ، badge سه‌نقطه | درخواست درحال پردازش |
| executing | آبی/فیروزه‌ای، پیشرفت محدود | Executor/Planner |
| uploading | فیروزه‌ای، نوار `progress` واقعی | IPC انتقال فایل |
| waiting_approval | طلایی، دکمهٔ تأیید/رد | Permission Layer |
| success | سبز بسیار کم، لبخند کوتاه | Verifier موفق |
| error | مرجانی/قرمز کم، اعلان بازیابی | خطای تأییدشده |
| offline | خاکستری، بدون pulse | وضعیت واقعی اتصال |
| sleeping | پلک آهسته، کم‌نور | حالت بی‌کار طولانی یا تنظیم کاربر |

حداقل دادهٔ رویداد: `{id,type,phase,source,startedAt,progress?,duration?,severity?,actions?}`. تغییر رفتار فقط از طریق Event Bus؛ دستگاه، رمزها و محتوا نباید مستقیم در UI لو بروند.

### قوانین تعامل
- `mini` به‌عنوان حالت پیش‌فرض باقی می‌ماند؛ **hover فقط نگاه/احوال‌پرسی، کلیک پیش‌نمایش را باز می‌کند**.
- کلیک آیکون باعث بازشدن ماژول واقعی می‌شود. `+` براساس صفحه کار می‌کند، نتیجه باید با اعتبارسنجی و تأیید ذخیره شود.
- کلیک بیرون، Escape، یا بی‌استفاده‌ماندن پنل را به mini برمی‌گرداند؛ بازبودن فرم/انتخابگر واقعی نباید دادهٔ نیمه‌تمام را حذف کند.
- حرکت کاراکتر با عملیات واقعی مربوط است؛ حالت تعجب، شادی یا ناراحتی بعد از تأیید وضعیت اجرا شود، نه به‌صورت بی‌دلیل.
- keyboard navigation، ARIA و `prefers-reduced-motion` از ابتدا، نه به‌عنوان وصلهٔ آخر.

## ۵. برنامهٔ توسعهٔ کم‌ریسک و مرحله‌ای

1. **حفاظت:** snapshot واقعی GitHub + سه VRM + بستهٔ حرکت، بررسی restore، بدون دست‌زدن به نسخهٔ اصلی.
2. **Motion Lab:** superellipse و state machine، ۱۰+ حالت، فریم‌های حرکت/آیکون یکپارچه، نسخهٔ standalone و تست reduced motion.
3. **Top Island:** اتصال موتور جدید به رویدادهای فعلی، رفتار click-only ثابت، تست واقعی pointer/Electron و برگشت سریع به مدل قبلی.
4. **Shortcuts, Pins, Reminders:** طراحی ماژول‌ها با workflow واقعی، واحدهای مشترک کارت/آیکون/فرم/تایید.
5. **Chat, Projects, Reports:** نمایش نتیجه با منبع و وضعیت معتبر، کیفیت تایپوگرافی فارسی و داده‌های واقعی.
6. **Avatar Studio 3D:** واردکردن سه VRM موجود، compatibility/VRMA/retargeting، presets و ثبت انتخاب؛ متناسب با GPU.
7. **Quality Gate:** تست‌های منفی و دسترس‌پذیری، screenshot مقایسه‌ای، performance profiling، Rollback، سپس ادغام انتخابی.

## ۶. معیارهای پذیرش (Definition of Done)

- همهٔ iconها در یک خانوادهٔ هندسی، قابل کلیک و دارای نام قابل فهم باشند.
- هیچ کنترل بی‌عمل، انیمیشن fake progress یا تایید نتیجه قبل از وقوع عمل باقی نماند.
- کاراکتر به حرکت موس/حالت عملیات واکنش مشخص و قابل تست نشان دهد.
- در mini رابط دیگری بی‌دلیل بالا نیاید و روی پنجره‌های دیگر overlay مزاحم باقی نماند.
- همهٔ ماژول‌های ورودی دارای Empty / Loading / Success / Error / No permission باشند.
- توان سخت‌افزاری با SVG fallback حفظ و انیمیشن‌های سنگین در حالت hidden غیرفعال شوند.
- نه پروژهٔ قبلی، نه فایل‌های شخصی و نه مدل‌های ذخیره‌شده با بازطراحی حذف/overwrite نشوند.
- تست عملی و ویدیوی مقایسهٔ before/after پیش از هر merge تهیه شود.

## ۷. محدودیت‌ها و حق استفاده

ویدیوها و اسکرین‌شات‌های پیوست **مرجع بصری** هستند؛ منبع کد یا مدل قابل استخراج اثبات‌شده نیستند. طراحی نهایی باید مستقل و مبتنی بر حقوق قابل استفاده باشد. حضور عبارت «Codex»، «GitHub»، «Apple Music» یا نام مدل در ویدیو به معنی اتصال خودکار آن سرویس‌ها در MARIA نیست. تبدیل ویدیو به مدل 3D کامل بدون فایل اصلی، ریتارگت و طراحی مستقل فقط یک تقریب خواهد بود. نسخهٔ مستقل Motion Lab برای بازبینی است، نه جایگزین کاراکتر بزرگ فعلی یا برنامهٔ درحال‌اجرا.
